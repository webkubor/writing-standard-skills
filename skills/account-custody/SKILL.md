# 账户托管运营前置检查（Account Custody Preflight）

Agent 替人操作社交账户，和替人写文章不是一回事。写文章只要内容对；**托管账户是穿着别人的身份说话**——说错一句，毁掉的是账户主人攒了几年的信用。

所以动任何操作之前，先过完这四道检查。**顺序不能换，缺任何一项就停，问户主，不猜。**

```
① 认平台   当前在哪个 App / 哪个入口，规则红线是什么
② 读人设   这个账户过去怎么说话的——读出来，不是选出来
③ 对口径   本次要发的内容，和已有人设吻合吗
④ 核环境   出口 IP、属地、设备指纹，和账户日常一致吗
```

> 与 `platform-voices` 的分工：`platform-voices` 管「**这个平台的读者爱看什么**」，是匿名创作者视角；本 skill 管「**这个具体账户的既有风格与安全边界**」，是受托人视角。两道都要过。

---

## ① 认平台：先知道自己在哪

**动笔前必须确认的三个事实**（看界面确认，不凭记忆）：

| 检查项 | 怎么确认 | 为什么 |
| --- | --- | --- |
| 当前 App 与页面 | 看当前前台应用与页面路径（主页 / 评论区 / 私信 / 搜索） | 同一个平台的不同入口，规矩完全不同：私信可以热络，评论区要克制 |
| 平台规则红线 | 加载该平台的扣分清单（X → `platform-voices` 的 Twitter 分册；小红书 → 小红书分册） | 违规不是风格问题，是封号问题 |
| 该入口的操作后果 | 发出去是公开可见，还是仅对方可见？可编辑还是不可撤回？ | 公开内容按「永久公开」对待 |

**平台红线速查**（详见 `platform-voices` 各分册，此处只列封号级）：

- **X**：主推挂外链断崖降权；短时间内高频发帖/关注/点赞触发反spam；多设备异地登录触发安全锁定。
- **小红书**：站外引流（微信号、外链）直接限流；营销词堆砌（“加V”“私聊”）判营销号；高频删除重发被判异常。
- **Reddit**：10:1 自推比红线，同一文案群发多版规直接封；未读版规发推广贴秒删。
- **微信公众号**：诱导分享、外部跳转链接受限。

## ② 读人设：先读，再写

**核心原则：托管场景下，人设不是创作时「选」一个原型（P1-P6），而是从账户历史里「读」出既有的那个，然后贴合它。**

5D 矩阵（`atomic-matrix.md`）的 Persona 是给匿名创作者挑角色用的。托管是反过来的：账户主人已经立了人设，你的任务是**测出它**。

### 读什么（按优先级）

1. **简介 / bio / 置顶内容**：户主自己声明的人设，最权威。
2. **最近 20 条发帖**：真实的语言习惯——
   - 用「我」还是「我们」？句长偏好？用不用 emoji、用什么频率？
   - 自曝多还是科普多？有没有固定栏目/口头禅/固定结尾？
   - 中英混杂？标点习惯（全角/半角/波浪线/省略号）？
3. **高互动内容（热帖）**：粉丝是因为什么关注这个账户的——这是不能丢的资产。
4. **回复与评论区**：户主怎么跟粉丝说话——热络还是高冷？用不用梗？

### 读出来的东西记成一张「人设卡」

```
账户人设卡（示例）
─────────────────────────────
账户：@xxx
平台：X
人称：我（从不用我们）
语气：粗粝真实 + 轻微自嘲；句短；几乎不用 emoji
内容域：独立开发踩坑 + 工具发布；不发政治、不蹭热点
固定习惯：推文末尾偶尔附一行命令；Thread 模式发布长内容
禁忌：从不抱怨用户；从不发「求转发」
─────────────────────────────
```

这张卡是后面所有操作的依据。**没读够 20 条历史之前，不动笔。**

## ③ 对口径：本次内容 vs 既有口径

拿到人设卡后，写任何内容前先过三问：

| 问 | 不过怎么办 |
| --- | --- |
| 这条内容放在他历史时间线里，粉丝会觉得是同一个人发的吗？ | 口吻重写，直到像 |
| 内容域越界了吗？（一个技术账户突然发美食探店） | 停下问户主：这是计划内的转型，还是误派？ |
| 有一条和固定习惯冲突吗（他从不求转发，这条求了） | 删掉冲突项，或问户主确认 |

**红线**：人设卡里记为「禁忌」的项，Agent 无权解禁——那是户主划的，要改也只能户主自己改。

---

## ④ 核环境：IP 与属地一致性

社交平台的风控不只看内容，还看**操作环境**。环境突变 + 行为突变同时出现 = 高危信号。

### 发帖前核对

| 检查项 | 一致性要求 | 不一致时的动作 |
| --- | --- | --- |
| 出口 IP | 与账户日常登录地同国/同区域（如日常在上海，突然从美国 IP 发帖就异常） | 切回日常区域节点再操作 |
| IP 类型 | 住宅/原生 IP 优于数据中心 IP（Twitter/小红书对机房 IP 都敏感） | 换住宅节点 |
| 操作节奏 | 模拟真人节奏：不要凌晨4点连发10条、不要秒回所有评论 | 拉开发帖间隔，跳过不合理时段 |
| 设备 | 同一账户尽量固定设备/浏览器指纹，避免每次都换环境 | 保持接管设备稳定 |

### 属地一致性举例

- 账户日常显示 IP 属地「上海」→ 接管时出口节点应选中国大陆（微博/小红书显示属地）或户主常用区域（X 无属地显示但风控同样看登录地）。
- 户主明确说「这个号是面向海外的人设」→ 节点选对应国家，且**保持稳定**，不要今天美国明天日本。

> 配套工具链：FlClash 选节点（改出口）→ DSH Go 手机操控（读屏点按）→ 本 skill（前置检查）。见博客 SOP：`https://webkubor.online/articles/phone-ai-agent-twitter`

## 检查单（每次接管会话开始时过一遍）

```
□ 确认了当前 App 与页面入口（不是凭记忆，是看了界面）
□ 加载了该平台规则红线 / 扣分清单
□ 读了账户简介 + 近 20 条历史 + 热帖 + 评论区习惯
□ 人设卡已建立（人称/语气/内容域/固定习惯/禁忌）
□ 本次内容对照人设卡过了三问（像不像/越没越界/冲不冲突）
□ 出口 IP 属地与账户日常一致；住宅 IP；节点稳定
□ 操作节奏拟人（间隔/时段合理）
□ 发布前草稿给户主预览确认（除非户主明确免检）
□ 户主划的禁忌项一条没碰
```

**任何一条打不上勾：停，问，不猜。**

## 为什么规则长这样

- **为什么先读再写**：人设是账户的信用资产。粉丝关注的是「那个人」，不是「一个会发帖的 AI」。口吻一变，掉粉比不发还快。
- **为什么环境一致性如此重要**：平台风控的核心信号是「环境突变 + 行为突变」。内容写得再像，IP 从上海跳到法兰克福再连发三条，账户直接进风控池。
- **为什么禁忌项 Agent 无权解禁**：受托关系的边界。户主没说的可以做，户主说了不做的绝对不做——这是托管能持续的前提。
- **为什么发布前要预览**：托管的第一周尤其关键。信任是靠「每次都和户主预期一致」攒出来的，一次大偏差就够户主收回权限。
