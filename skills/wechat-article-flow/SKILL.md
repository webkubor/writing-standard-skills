# 公众号图文生产流程

这是流程门禁，不是风格分册，也不是排版规范。

- 平台受众心智与语气：看 `platform-voices`。
- 四步写作骨架与自检：看 `how-to-write`。
- 讲稿/长文姿态：看 `talk-text-review`。
- 字号、留白、配色、分页：不在本 skill，归 `facet`。

本 skill 只回答一件事：**一篇公众号图文，从选题到交付，按什么顺序做、每步拿什么出门禁。**

---

## 0. 总原则

1. 每一步先给结果、等确认，再进下一步。用户说「一次性出完」才允许连跑。
2. 不编造事实、数据、案例。没有第一手材料就换题，或标「需核实」。
3. 交付不等于发布。写入草稿箱前必须让用户过目标题、封面、正文要点；正式发布必须单独、明确确认。
4. 不把单次发布的账号资料、Secret、内部路径写进流程。本 skill 只沉淀可复用方法。

---

## 1. 输入四问

动笔前先问清四件事，可以一句话问完：

1. 主题：这篇讲什么
2. 读者：给谁看（客户 / 同行 / 大众 / 内部）
3. 目的：看完要做什么（了解 / 咨询 / 报名 / 转发）
4. 篇幅与调性：短文 / 常规 / 深度长文；专业、亲和还是活泼

用户说「你看着办」时，默认「常规 1500–2500 字、专业但易懂、面向成熟读者」，并在交付时声明采用了默认值。

---

## 2. 选题拷问

一轮问完六个维度，每个维度都给推荐答案，用户回「按推荐来」就能全采纳：

| 维度 | 要问什么 |
|---|---|
| 凭什么是你写 | 手上有什么别人没有的一线数据、真实案例、踩坑记录 |
| 读者此刻的处境 | 他在什么场景下点开，当时正在烦什么 |
| 真材实料 | 有哪些数字、案例、截图、原话可写；没有就改成观点文或换题 |
| 唯一动作 | 看完希望读者做的那一个动作 |
| 不能写什么 | 保密、竞品、客户名、内部数据 |
| 怎么算成功 | 阅读、咨询、转发，还是只做销售素材 |

能自己查的事实不要问用户。用户明确说「别问了直接写」才跳过。

---

## 3. 文体与骨架

先判文体，再选骨架。一篇只用一种骨架，不混用。

| 文体 | 读者带走什么 | 骨架 |
|---|---|---|
| 干货型 | 一套可照做的方法 | 问题 → 代价 → 方法拆解 → 落地步骤 |
| 案例型 | 别人怎么做，我能抄什么 | 结果 → 背景 → 关键决策 → 可复用点 |
| 观点型 | 一个判断和它的依据 | 反常识断言 → 证据 → 对立面回应 → 结论 |
| 公告型 | 变了什么，我要做什么 | 变化 → 影响 → 时间线 → 行动 |
| 转化型 | 为什么现在行动 | 钩子 → 兴趣 → 价值证明 → 行动 |

给三个切入点让用户选：每个一句话写清「切入点 + 读者为什么在意 + 我们能给出什么别人给不了的东西」。用户不选就走第一个。

---

## 4. 标题判据

标题不是最后一步灵感，是正文的承诺。

1. **前 15 字内出现对象与价值，或冲突。** 被折叠的是后半段。
2. **总长 18–28 字为参考区间**，微信标题还有字节上限；发布前用自家账号实测截断位置。
3. **承诺必须在正文前 1/3 兑现。** 说「三个方法」就写三个；首个分点不能藏在结尾。
4. 每篇出 3–5 个备选，分直给型、疑问型、利益型，标字数、前 15 字、适用场景（信息流 / 朋友圈 / 搜索）。
5. 不用「震惊」「必看」「99% 的人不知道」，不用与正文无关的悬念。

---

## 5. 正文

- 开头三段：第一段给具体场景、数字或冲突；第二段说清这篇解决什么；第三段可选，给结构预告。
- 一段一个意思，手机阅读下每段不超过 5 行。
- 每个小标题下至少有一个可核验的具体信息：数字、步骤、案例或反例。
- 删掉空泛的时代背景开场、人尽皆知式套话、管理黑话和口号式愿景收尾。
- 姿态用经验陈述，不用布道：写「我试了之后发现」，少写「你应该」。
- 判断要标清是个人判断还是已核实事实。
- 结尾停在具体判断或真开放问题上；不要空洞升华。

---

## 6. 配图

1. 先定风格锚点：画风、主色调、是否出现人物、光线。整篇共用一组词。
2. 生成前说明积分消耗，并确认张数；默认封面 1 张 + 正文 2 张。用户明确说不要图才跳过。
3. 图里不要出现文字、logo、二维码、真实人物肖像；文字后期在编辑器里加。
4. 每张图配一句图注，写清想让读者看懂什么。
5. 公众号编辑器只稳定抓取公网 URL。拿不到公网 URL 时，交付本地图片 + 占位提示，并说明需手动插入；不要假装已上传。
6. 封面单独给用户确认。

---

## 7. 排版交接

本 skill 不定义字号、留白和配色。定稿后按目标工具交接：

- 粘进公众号编辑器：产出纯内联样式 HTML，容器用 `section`，无 `class`、无 `<style>` 块、无脚本、无百分比单位。
- 走自建脚本：按脚本实际支持的 Markdown 子集供稿。不支持表格、列表、链接时，就改写成段落和二级标题，不静默丢内容。
- 交付时说明粘贴方法：浏览器打开 HTML → 全选复制 → 后台编辑器粘贴。直接复制源码文本会失败。

排版数值与主题归 `facet`；本仓只保证内容结构不被排版工具吃掉。

---

## 8. 合规自查

逐项过，结果分成「已处理 / 需用户确认」两类：

1. 广告法极限词：最、第一、顶级、国家级、绝对等。
2. 诱导分享：转发领资料、不转发看不到等门槛表述。
3. 数据出处：行业数字、用户量、增长率、引用都要有来源或标为示例。
4. 隐私：真实姓名、电话、公司内部数据、客户名。
5. 版权：图片、段落、观点是否可商用；AI 生成图也要人工确认没有混入第三方品牌元素。
6. 平台要求：若平台或当地规则要求 AI 生成标识，按平台后台声明处理；与个人 IP 表达冲突时，先让用户确认落点，不擅自写进正文。

---

## 9. 交付与门禁

交付清单：

- Markdown 备份
- 3–5 个标题备选，标注字数、前 15 字、适用场景
- 合规自查清单，标出已处理和待确认
- 可粘贴 HTML 或脚本友好 Markdown
- 配图文件与图注；未上传的图标明「需手动插入」
- 发布留痕位置：slug、链接、时间

门禁：

1. 写入草稿箱前，用户明确确认标题、封面、正文要点。
2. 未配置公众号连接器时，如实说明做不到直接写入草稿箱，不要虚构结果。
3. 正式发布是不可逆动作，必须单独、明确确认，不因为用户说过「帮我发」就代点发布。
4. 发布后记录真实链接与时间；失败则记录失败原因，不把草稿 media_id 当作发布成功。
