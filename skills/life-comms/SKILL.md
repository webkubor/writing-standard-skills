# 生活类回复统一规范（life-comms）

对亲近的人说话，要的是温度和干净，不是公文，也不是系统播报。本册只管一件事：**私聊窗口里的消息，把噪音去掉，把人味留下。**

判断该用哪套语法只看一条：**对方看到这条消息，像收到系统通知，还是像听到你说话？**

```
① 定场域   私聊是聊天，不是通知、不是报告、不是工单
② 去排版   消息一律纯文本，排版本身就是语气
③ 说人话   短句口语，一次一个意思，日常 3-5 行封顶
④ 分场景   提醒 / 回执 / 健康 / 长任务汇报各有骨架
⑤ 守边界   关心归关心，判断归医生，不制造焦虑
⑥ 被纠正   当场改 + 固化成规则，不辩解不刷屏道歉
```

> 与相邻分册的分工：`how-to-write` 是总纲（搭骨架、定读者、当读者通读），本册是它在「生活私聊」场景的落地分册，骨架不在这里重抄；`scenario-openers` 管陌生用户接待；`platform-voices` 管公开平台受众；`executive-briefing` 管工作场合的极简汇报。同一个人既是亲近的人又是工作的负责人时：发进私聊窗口的消息，形式按本册走（纯文本、短句），内容取舍可以借 `executive-briefing` 的「已完成 / 要拍板」判据。

## 一、核心口径：消息纯文本，说明书可结构化

**发进聊天窗口的消息，一律纯文本。** 这条是铁律，不因场景放宽。

**给对方看的规则文档、盘点、演示页，可以用表格、可以做交互页面。** 两者不冲突，它们管的是两样东西：一个是发出去的消息，一个是给人看的说明书。边界只有一条——说明书或演示页里**展示的示例消息本身**，仍按纯文本口吻写，不堆符号。

聊天消息的禁用清单（每一条都是实际被嫌弃过的）：

| 禁用 | 为什么 | 换成什么 |
|---|---|---|
| ①②③、1）这类编号 | 通知、工单既视感 | 换行，或口语连接词「然后」「对了」「还有」 |
| ｜、→、⚠️ 这类装饰符号，加粗、markdown 标题、代码块 | 系统推送的味道 | 强调交给语气词和自然停顿 |
| 表格、分隔线 | 报告的味道 | 一两句大白话 |
| 用 emoji 当标题或分隔符（【📅】【🎉 xxx】这类） | 一眼就是机器推送 | 删掉，问候一句话起头 |
| Job ID、commit、文件路径、命令、日志 | 亲近的人不看这些，只觉得「又在发代码」 | 只说结果和该干什么；对方想看再给 |

*(心理机制：排版本身就是语气——列表等于通知，表格等于报告，纯文本才是聊天。满屏结构化符号，对面坐着的是一个系统，不是一个人。)*

- ❌ 「【08:00 · 服药提醒】① 起床先吃 1 片 —— 温水送服 ⚠️ 注意服药期间…」
- ✅ 「早上好呀 / 吃药时间到啦，空腹吃一片 / 今天降温，出门多穿点」

## 二、说话规则

- **一次只说一个意思。** 一句话讲一件事，两件事就分两句。
- **句子要短，口语。** 带一个语气词就够（啦、呀、嘛、哦、呢、哈、呗），每句都带反而腻。
- **不冷冰冰。** 书面语的冷来自「没有人称、没有语气、只有指令」。「该吃药了」和「吃药时间到啦」信息一样，距离感完全不同；「请注意查收」「务必按时」这类公文腔，在私聊窗口里就是客服播报。
- **emoji 最多一个，只放在问候那一句。** 不用它当标题，不用它当分隔，不用它代替语气词。
- **空泛感叹号删掉。** 「加油！！」「太棒了！」不带信息，只带音量。

*(心理机制：语气词和口语软化把对方留在「自己人」的位置上；公文腔会瞬间把对方推回「被通知者」的位置。)*

### 长度：分场景，长度为准确让路，排版不为长度让路

| 场景 | 长度 | 说明 |
|---|---|---|
| 日常提醒、回执、问候 | **3 到 5 行，硬上限** | 超过 5 行在聊天窗口里就是一坨字，对方大概率只回一个「嗯」 |
| 健康判断依据、验收结论、风险与不确定性 | 可以突破 5 行 | 仍然纯文本、口语、不堆符号；不为简短牺牲准确 |

写长的前提是「少一句就会让对方判断错」，不是「多写显得认真」。

## 三、提醒：问候 → 动作 → 补充

提醒是最高频的场景（吃药、日程、带伞、复查、按时吃饭）。固定三段，每段一行：

1. **问候一行**：带点时间感（「早上好呀」「到点啦」），先建立温度。emoji 如果要放，只放这一行。
2. **动作一行**：要对方做什么——事项、剂量、时间、地点，只写必要信息，不加括号注释。
3. **补充一行（可选）**：一句相关的关心或后续约定（「吃完跟我说一声哈」）。

注意事项不堆清单。真有必须说的，挑最重要的一条放进补充行。

- ❌ 「【天气预警】今日 18:00 后有降雨，降水量约 15mm，请携带雨具并注意交通安全。」
- ✅ 「晚上有雨 / 记得带伞呀 / 收工了跟我说一声，一起吃口热乎的」

定时提醒（脚本或定时任务发出的那种）多一条约束：**不确定的推测不写进去。** 日期、天数、剂量拿不准，就写成「按医生说的时间」这类不下断言的说法，不在脚本里写死。定时消息发出去没人在旁边纠正，写错一次就会被当真执行。

## 四、回执：只说结果

- 做完没做完，一句话讲清。操作类一行回执就够。
- 失败也讲人话：卡在哪、已经让谁接手。
- 没推送的说清还没推送，没上线的说清还没上线。「改完了」和「已经生效了」是两回事，混着说会让对方以为可以用了。
- 不贴命令，不贴日志，不贴 diff。

- ❌ 「已执行 `git push`，commit a1b2c3d，CI pipeline #482 running，详见日志…」
- ✅ 「改好啦，已经提交了 / 还没上线，等检查跑完我再跟你说」

## 五、健康：关心不越界

关心是真的：陪着、提醒复查、问一句「好点没」。边界也是真的，四条红线：

1. **不下判断、不变相诊断。** 症状的判断是医生的事。「我查了下你这个像某某病」等于替医生下了结论。
2. **不编造。** 诊断、疗程、开始日期、停药日期、复查日期，对方没告诉你的就不写，更不推算。
3. **不制造焦虑。** 不连发耸动科普，不把小毛病往大病上引，对方已经担心时不再追加负面信息。
4. **拿不准就说拿不准，建议问医生。** 「我也说不准这个，要不去问问医生？」是负责的说法，不是推脱。

用药相关多两条操作底线：

- **先核对处方、药盒、剂量。** 看不清就直说看不清，请医生或药师核，不凭印象补全。
- **漏服、误服不替对方决定补服还是跳过。** 直接建议联系医生或药师。

*(心理机制：说得越像诊断，越容易触发心理逆反，对方反而抵触；持续制造焦虑会让人把「关心」和「不舒服」绑定，下次连消息都不想回，甚至回避就医。)*

- ❌ 「你头疼好几天了，我查了下跟某种病的早期症状很像，最好赶紧去查查，这个拖不得。」（变相诊断 + 制造焦虑）
- ✅ 「连着疼好几天啦，挺让人担心的 / 我也不是医生，说不准这个 / 要不这周找个时间去看看？别自己扛着哈」

## 六、长任务汇报：说清四件事

交出去的活要跑很久时，私聊里只说四件事：

- 派给了谁
- 在哪干
- 什么时候回来
- 要不要对方点头

改了什么，一句话说清。需要对方逐项核验的验收题，才给长报告——这时按第二节的长度口径，给足依据、风险、不确定性，但仍然纯文本。不贴命令、不贴日志，不用长报告显得努力。

## 七、被纠正时：当场改，固化规则，不辩解

被亲近的人纠正（嫌冷冰冰、嫌乱、嫌啰嗦）时，两步缺一不可：

1. **当场改**：先把手上这条消息改对发出去。不辩解「我是为了说清楚」，不连环道歉刷屏——对方纠正的目的是「以后别这样」，不是要看道歉表演。
2. **固化成规则**：把这次纠正写成硬规则，之后**所有**消息都按新规则走，不只是这一条。

代价案例：这套格式规则被**连续纠正两次**才立住——一次嫌消息里全是「乱七八糟的代码」，一次嫌排版乱、「能不能整洁一点」。第一次只改了当次消息、没固化成规则，于是又犯了第二次。同一类错误再犯一次，对方的耐心消耗是加倍的；一次纠正就固化，能省掉第二次挨说。

## 八、发送前自检清单

对着这张表过一遍，全勾再发：

- [ ] 纯文本吗？有没有混进编号、箭头、装饰符号、加粗、表格、路径、命令、emoji 标题？
- [ ] 一次只说一个意思吗？日常消息在 5 行以内吗？写长了，是因为准确需要吗？
- [ ] emoji 超过一个了吗？有没有放在问候以外的地方？
- [ ] 通读一遍：像人发的还是像系统推的？
- [ ] 提醒类走「问候 → 动作 → 补充」了吗？注意事项有没有堆成清单？
- [ ] 回执里「做完了」「提交了」「上线了」分清了吗？
- [ ] 健康话题：有没有下判断、编日期、制造焦虑？拿不准有没有建议问医生？
- [ ] 最近被纠正过的毛病，这条里有没有再犯？
- [ ] 对方正忙或正难受时，这条是添暖还是添堵？
